# XAUUSD provider eligibility contract (synthetic v1)

`xau.provider-eligibility.v1` is an isolated fail-closed contract in `backend/app/data/provider_contracts.py`. It is not imported by provider clients, ingestion, the application service, or the archive. A provider can be marked eligible only when every required gate has an authoritative reference and review timestamp with an affirmative finding. A denial or missing/unknown gate leaves the source unavailable. The gate set covers account/product retrieval rights, raw and normalized retention, internal analysis, external AI inference, attribution, historical coverage, supported intervals, timestamp semantics, pagination/completeness, rate limits, freshness, upstream rights, and expiry/deletion obligations.

`xau.retrieval-completeness.v1` describes one requested XAUUSD interval and range, its explicit test freshness threshold, supported intervals, and ordered page evidence. Its strongest positive status is `page_chain_complete`; this means only that the supplied chain terminated with consistent records. It rejects unsupported intervals, stale/future retrievals, identity mismatches, broken/repeated cursor chains, invalid timestamps, empty ranges, and duplicate or conflicting candle identities. It cannot prove that a provider omitted no source bucket, that the account is entitled, or that a source contract is authoritative. Provider-specific completeness evidence and live/source eligibility remain separate prerequisites.

Synthetic tests exercise complete and partial retrievals, missing/duplicate pages, conflicting candles, invalid timestamps, stale data, identity mismatch, unsupported intervals, and denied permission. Existing archive tests cover retention expiry, revision lineage/invalidation, generation fencing, crash recovery, and concurrent writers. No provider is populated as eligible from the current source review; Twelve Data and SiftingIO remain UNVERIFIED. No provider call or activation is part of this contract.
