# AI analyst workflow contract

Status: **VERIFIED for isolated synthetic immutable request/response/report persistence and read-only projection; external model use BLOCKED pending source permission, provider configuration and separate activation authorization.** No paid or external AI request is made by this workflow.

`backend/app/ai/analyst.py` accepts the validated deterministic `EvidencePacket`, a `ContextSnapshot`, input/derived manifest identities and digests, provider/model identifiers, prompt version, configuration metadata, an injected completion function and a mandatory manifest-binding verifier. It builds a versioned evidence-only prompt and sends no network request itself. A caller must verify the stored manifest/output pair before the model boundary; `SyntheticArchive.verify_analyst_binding` checks the immutable pair and rejects invalidated evidence for new dispatch. This archive helper is synthetic-only and disconnected from the service.

If deterministic evidence is insufficient, the workflow returns the existing verified deterministic NO TRADE response and does not invoke completion. Completion exceptions return `unavailable`; malformed or ungrounded responses return `invalid_response`. `AnalystResponseV1` wraps the existing `AnalysisResponse` with bullish/bearish scenarios, neutral conditions and separately cited contextual interpretations. Technical claims pass the existing `validate_response` contract for evidence references, timeframe membership, numeric price citations, supported levels, risk/reward, missing inputs and deterministic quality gates. Context citations must resolve to records from available feeds; unverified, stale, incomplete or conflicting feeds cannot support a claim. The response provider/model/request ID must match the bound provenance. Provenance binds both manifest IDs/digests, provider/model/request identifiers, prompt version, non-secret configuration metadata and creation time.

The analyst result also reports market-data status and retrieval timestamp. Available H4 evidence is rejected while H4-03 remains deferred. The current response schema supports bias, stance, evidence-linked rationale, per-timeframe direction/structure, setup levels, invalidation, risk/reward, confidence explanation, conflicts, missing information and reasons to avoid. Macro/calendar/news context is included in the prompt with explicit feed states and separate record citations.

`backend/app/ai/persistence.py` provides the isolated synthetic persistence boundary. It accepts only an injected completion callable, constructs the existing prompt, and atomically appends versioned AI request and response records plus an AI report record for `complete` and `insufficient_evidence` outcomes. Request records bind the exact prompt digest, prompt version, provider/model IDs, configuration metadata and the persisted input/output/derived digests. Response records bind the exact injected completion text when it passes credential-content checks, the validated `AnalystRun` and explicit failure states; malformed or unavailable outcomes do not create report records. Credential-like metadata keys and credential-like prompt text are rejected; credential-like response text is omitted and the result becomes invalid. Canonical digests use the registered canonical JSON profile and framed digest codec; record digests are not embedded in their own payloads. Exact replay is idempotent; identity reuse with changed or partial content fails.

The synthetic archive schema is version 3 and is new-file-only; it does not migrate version 2 or production databases. SQLite foreign keys and append-only triggers protect request, response and report records. The write transaction rechecks that the input manifest is eligible and the derived output links are still valid. `project_analysis` verifies each record digest and request/response/report linkage in its own read snapshot. Previously persisted reports remain visible with the existing historical invalidation warning. The API and dashboard show report status, outcome, persisted identity/digests, provider/model and prompt version, scenarios and missing evidence. All such results remain labelled synthetic and are not live recommendations.

`backend/tests/test_ai_evidence.py` verifies the injected-success path, manifest binding in prompts, missing-H4 NO TRADE without model invocation, transport failure, malformed output, and rejection of invented news/price claims. `backend/tests/test_ai_report_persistence.py` and `backend/tests/test_analysis_projection.py` cover report persistence, exact replay, failed/rejected states without reports, invalidation, rollback, digest/linkage verification and read-only projection. `backend/tests/test_analysis_provenance.py` exercises persisted input manifest → deterministic derived output → context snapshot → insufficient-evidence analyst result.

No model is configured, selected, called or paid in these tests. Existing per-request/daily safeguards remain unchanged; no fixed monthly cap is introduced.
